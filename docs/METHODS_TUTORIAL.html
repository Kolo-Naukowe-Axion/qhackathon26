1. The problem: a tiny flow shop

Job
One part that must be made, here Z1, Z2, Z3.
Operation
One step of a job on one machine, e.g. "Z1 on the lathe, 2 hours".
Schedule
A start time for every operation.
Feasible
A schedule that obeys all the rules. Infeasible = breaks at least one.
Makespan
The time at which the last operation finishes. Smaller is better.
Optimal
The best possible value; no feasible schedule does better.

Each job (part) Z1, Z2, Z3 visits the machines in the same fixed order: T (lathe) → F (milling) → S (welding). A machine processes one operation at a time; an operation cannot start before the same job's previous operation has finished; operations are not interrupted. The goal is to minimise the makespan Cmax, the finishing time of the last operation.

Instance A uses Z1, Z2 on T → F; Instance B uses all three jobs and machines. When every job has the same route this is a flow shop, a special case of the job shop.

Why these optima are certainly optimal

Instance A is a two-machine flow shop, solved exactly by Johnson's rule (Johnson 1954): put jobs whose first-machine time is smaller than their second-machine time first, in increasing order of the first-machine time; the remaining jobs last, in decreasing order of the second-machine time. Z2 (1 < 2) goes first and Z1 (2 > 1) last, giving makespan 4.

Instance B has a simple lower bound. Machine T must process 2+1+2 = 5 h of work, and whichever job T finishes last still needs F and S afterwards, at least minj(Fj+Sj)=3 h. So Cmax≥5+3=8. The slide schedule reaches 8, so it is optimal. This kind of bound is a cheap, convincing argument to show the jury next to any solver result.

The baseline instances are small enough that the optimum is known exactly. They test whether the formulation and pipeline are correct; they cannot show that a quantum method is fast or better than classical methods.

2. What a QUBO is, built up from scratch

This section starts from nothing and ends with the exact matrix the repository builds. Read it with a pencil: every step is small, and every number can be checked by hand.

2.1 The vocabulary

Bit (binary variable) xi
A variable that can only be 0 or 1. In scheduling, a bit is a yes/no decision: 1 = "yes, do this", 0 = "no". The subscript i is just a name tag: x1,x2,x3,…
Bitstring x
All bits written next to each other, e.g. 0110 means x1=0, x2=1, x3=1, x4=0. One bitstring = one complete candidate answer. With n bits there are 2n bitstrings (each extra bit doubles the count).
Energy E(x)
A rule that turns a bitstring into one number. Lower is better. "Minimise E" means: among all bitstrings, find the one with the smallest number.
Coefficient
A fixed number inside the energy rule. We (the modellers) choose coefficients; the solver chooses bits.
Linear term
Coefficient × one bit, e.g. 3x1. Adds 3 if x1=1, nothing if x1=0.
Quadratic (pair) term
Coefficient × two different bits multiplied, e.g. 4x1x2. A product of bits is 1 only if both are 1, so this adds 4 only when both decisions are taken together.
Constant c
A number with no bit attached. It is added to every bitstring equally.
QUBO
Quadratic (at most pairs of bits are multiplied), Unconstrained (every bitstring is allowed as input), Binary (bits are 0/1), Optimisation (find the minimum).

2.2 Worked example A: evaluating an energy by hand

Take two bits and this energy rule:

E(x1,x2)=3x1−2x2+4x1x2+1

Two bits give 22=4 bitstrings. Plug each one in:

x1x2substitutework it outE
003·0−2·0+4·0·0+10−0+0+11
013·0−2·1+4·0·1+10−2+0+1-1
103·1−2·0+4·1·0+13−0+0+14
113·1−2·1+4·1·1+13−2+4+16

The smallest energy is −1, at x1=0, x2=1. Read the coefficients as prices: switching on x1 costs 3; switching on x2 earns 2 (a negative price); switching on both costs an extra 4. A solver's whole job is this table, except that real problems have far too many rows to write out (8 bits: 256 rows; 39 bits: about 550 billion).

2.3 A useful fact: a bit times itself is itself

0·0=0,1·1=1⟹x2=x for every bit x

So any squared bit can be replaced by the bit itself, e.g. 5x12=5x1. This tiny fact is what lets linear terms live inside a matrix (2.4) and what makes the penalty expansions in 2.5 work.

2.4 Deriving the matrix form E=x⊤Qx+c

Put the coefficients in a square grid Q (a matrix; qij is the entry in row i, column j) and write the bits as a column x. x⊤ ("x transposed") is the same bits written as a row. For two bits:

Q=[q11q12q21q22],x=[x1x2],x⊤=[x1x2]

Step 1: matrix times column. Each row of Q is multiplied entry by entry with the column, and the products are added. One number per row:

Qx=[q11q12q21q22][x1x2]=[q11x1+q12x2q21x1+q22x2]

Step 2: row times that column. Multiply matching entries and add. The result is a single number:

x⊤Qx=[x1x2][q11x1+q12x2q21x1+q22x2]=x1(q11x1+q12x2)+x2(q21x1+q22x2)=q11x1x1+q12x1x2+q21x2x1+q22x2x2

Step 3: simplify. Use x1x1=x1, x2x2=x2 (2.3) and x2x1=x1x2:

x⊤Qx=q11x1+q22x2+(q12+q21)x1x2
Result. The diagonal entries (q11,q22) are the linear coefficients. The two mirror-image off-diagonal entries add up to the pair coefficient. The constant is not in the matrix; it is carried separately as c. With more bits nothing new happens: every pair of bits gets its own two mirror cells, and in general
E(x)=x⊤Qx+c=∑i∑jqijxixj+c

Only the sum q12+q21 matters, so there are two common ways to fill the matrix: upper-triangular (the whole pair coefficient above the diagonal, 0 below; this is what the repository does) or symmetric (half above, half below). Worked example A (linear 3 and −2, pair 4, constant 1) both ways:

Qupper=[340−2],Qsym=[322−2],c=1

Check with numbers, upper form, x=(1,1):

Qx=[340−2][11]=[3+40−2]=[7−2]x⊤Qx=[11][7−2]=7−2=5E=5+c=6

Same as the last row of the table in 2.2. ✓

The shortcut you will actually use: the sub-block rule

In ∑i∑jqijxixj every entry qij is multiplied by xixj, which is 1 only if bit i and bit j are both 1.

To get the energy of a bitstring: keep only the rows and columns of bits that are 1, add up every entry where those rows and columns cross, then add the constant.

For x=(1,1): keep everything, 3+4+0−2=5, plus 1 gives 6. For x=(0,1): keep only row and column 2, the single entry −2, plus 1 gives −1. ✓

2.5 Turning a rule into a penalty: "start exactly once"

A QUBO accepts every bitstring, so a rule cannot be forbidden directly. Instead we add a penalty: a piece of energy that is 0 when the rule is obeyed and positive when it is broken. Then rule-breaking bitstrings can never be the cheapest.

Suppose an operation may start at hour 0 (x1) or hour 1 (x2). The rule "exactly one start" says x1+x2=1. The amount we miss by is x1+x2−1; it is −1 for no start and +1 for two starts, so we square it to make every miss positive:

P=(x1+x2−1)2

Expanding, step by step. A square is a bracket times itself. Multiply each of the three terms in the first bracket by each of the three in the second (9 products), then use x2=x and collect like terms:

P=(x1+x2−1)(x1+x2−1)=x1x1+x1x2−x1first term×all three+x2x1+x2x2−x2second term×all three−x1−x2+1(−1)×all three=x1+x1x2−x1+x1x2+x2−x2−x1−x2+1use xixi=xi=1−x1−x2+2x1x2collect

Collecting: x1 gets +1−1−1=−1; x2 gets −1 the same way; x1x2 gets +1+1=+2; the constant is +1. Check: (0,0) gives 1, (1,0) gives 0, (0,1) gives 0, (1,1) gives 1−1−1+2=1. Zero exactly when one start is chosen. As a matrix:

P=x⊤[−120−1]x+1

Three possible starts (hours 0, 1, 2 → bits x1,x2,x3). The same expansion gives

(x1+x2+x3−1)2=1−x1−x2−x3+2x1x2+2x1x3+2x2x3

always −1 on each bit, +2 on every pair and +1 constant, whatever the number of starts. The penalty is simply (number of starts − 1)²:

x1x2x3starts chosenpenaltyrule
0000(0−1)2=1✗
0011(1−1)2=0✓
0101(1−1)2=0✓
0112(2−1)2=1✗
1001(1−1)2=0✓
1012(2−1)2=1✗
1102(2−1)2=1✗
1113(3−1)2=4✗

That answers the earlier question: choosing hours 0 and 2 (101) costs 1. In matrix form, with the sub-block check for 101 (keep rows and columns 1 and 3: −1+2−1=0, plus constant 1 gives 1 ✓):

x⊤[−1220−1200−1]x+1

2.6 From coefficients to the upper-triangular matrix: the general rule

Sections 2.4 and 2.5 filled matrices by hand. Here is the rule that does it for any number of bits. Write every QUBO in this standard form, with one name per kind of coefficient:

E(x)=∑i=1naixi+∑i<jcijxixj+c
ai (linear coefficient)
the number in front of the single bit xi.
cij (pair coefficient), i<j
the number in front of the product xixj. Each pair is listed once, with the smaller index first: c12, never c21. If a pair does not appear, its cij is 0.
c (constant)
the number with no bit. Careful: c with no subscript is the constant; cij with two subscripts is a pair coefficient.

The rule

Qij={aiif i=j(diagonal)cijif i<j(above the diagonal)0if i>j(below the diagonal)
The constant c stays outside the matrix: E(x)=x⊤Qx+c.

Pictured for n bits, the linear coefficients run down the diagonal and the pair coefficients fill the triangle above it:

Q=[a1c12c13⋯c1n0a2c23⋯c2n00a3⋯c3n⋮⋮⋮⋱⋮000⋯an]

Row i, column j holds the coefficient of xixj; on the diagonal xixi=xi, so the diagonal holds the coefficient of xi alone.

Why the rule is correct

Step 1. Write out x⊤Qx as a double sum (2.4) and sort its terms into three groups: on, above and below the diagonal:

x⊤Qx=∑i∑jQijxixj=∑iQiixixi+∑i<jQijxixj+∑i>jQijxixj

Step 2. In the last group, swap the names of the two indices (call the larger one j and the smaller one i); then it is also a sum over i<j. Use xjxi=xixj and xixi=xi:

x⊤Qx=∑iQiixi+∑i<j(Qij+Qji)xixj

Step 3. Compare, term by term, with the standard form E(x)−c=∑iaixi+∑i<jcijxixj. They are equal for every bitstring exactly when

Qii=aiandQij+Qji=cij(i<j)

Step 4. Only the sum Qij+Qji is fixed, so we may choose how to split it. Putting everything above the diagonal (Qji=0) gives the upper-triangular rule in the box. Splitting it evenly gives the symmetric form, used by some software:

Qijsym={aiif i=j12cijif i<j12cjiif i>j

Both matrices give the same energy for every bitstring. The repository (and this tutorial) use the upper-triangular form.

Example 1: worked example A

E=3x1−2x2+4x1x2+1, so a1=3, a2=−2, c12=4, c=1:

Q=[a1c120a2]=[340−2],c=1

Example 2: the "no two at once" penalty

If xa = "job A on the machine at hour 0" and xb = "job B on the same machine at hour 0", both cannot be true. The penalty is the product xaxb: it is 1 for the clash and 0 otherwise. In standard form: aa=0, ab=0, cab=1, c=0. So

Q=[0100],c=0

A job-order rule ("the second step may not start before the first finishes") works the same way: cij=1 for every pair of start times that would put the steps in the wrong order. In the bigger matrices of 2.7 and 3.6 these are the orange (machine clash) and green (job order) cells.

Example 3: "exactly once" with three possible starts

From 2.5: (x1+x2+x3−1)2=1−x1−x2−x3+2x1x2+2x1x3+2x2x3. Read off a1=a2=a3=−1, c12=c13=c23=2, c=1, and place them:

Q=[a1c12c130a2c2300a3]=[−1220−1200−1],c=1

Example 4: the other direction, from a matrix to an energy

Given

Q=[2−1000300−4],c=5

read the diagonal as a1=2,a2=0,a3=−4 and the upper triangle as c12=−1,c13=0,c23=3:

E(x)=2x1+0·x2−4x3−x1x2+0·x1x3+3x2x3+5=2x1−4x3−x1x2+3x2x3+5

Check one bitstring, x=(1,1,0): from the formula 2−0−1+0+5=6; by the sub-block rule (keep rows and columns 1 and 2) 2+(−1)+0+0=1, plus 5 gives 6 ✓.

The recipe

  1. Expand every penalty and objective into single-bit terms, pair terms and a constant (using x2=x).
  2. Add up all contributions to the same xi: that total is ai. Add up all contributions to the same pair xixj (smaller index first): that total is cij. Add up all constants: that is c.
  3. Put ai at (i,i), cij at (i,j) with i<j, and 0 everywhere below the diagonal.

Section 2.7 runs this recipe on a complete scheduling problem.

2.8 How a computer stores a QUBO

Most entries are 0, so programs store only the non-zero ones. The repository's model files (output/stage1-preparation/*.qubo.json) contain exactly the three parts of x⊤Qx+c:

field in the filewhat it ismini-problem value
linearthe diagonal of Q[−1, −1, −1, −1]
quadraticlist of [row, column, value] above the diagonal[0,1,2], [0,2,1], [1,3,1], [2,3,2]
offsetthe constant c2

(Programs count rows from 0, so A0 is row 0.) The VeloxQ SDK, D-Wave tools and the QAOA code all accept this same information. Lucas 2014 [PDF] shows how many classic problems are written in this form.

Why go to this trouble?

Because three very different machines all accept exactly this input: quantum annealers (hardware whose qubits physically settle into low-energy states), QAOA (a circuit for a gate-based quantum computer, §8) and quantum-inspired classical solvers such as VeloxQ. Write the problem once as a matrix and you can hand it to any of them.

3. The time-indexed QUBO: general recipe, then Instance A
Time-indexed
One bit for every (operation, start hour) pair. The bit is 1 if that operation starts at that hour.
Horizon H
A deadline we test: "can everything be finished by hour H?". Only start hours that fit before H get bits.
Interval [s,e)
The time an operation occupies its machine: from start s up to, but not including, end e=s+duration. "Not including" means a machine freed at hour 3 can start a new job at hour 3.
Window pruning
Leaving out start hours that can never work, so fewer bits are needed.
Heuristic solver
A method that usually finds good answers fast but cannot prove an answer is the best or that none exists. Annealers, QAOA and VeloxQ are heuristics.

This is the method of Venturelli et al. (2015) [PDF], used by the repository. Each step is written first for any number of jobs and machines, then applied to Instance A, keeping both the scheduling names and the xi, Qij names side by side.

3.1 Step 1: the problem in general, and the bits

A flow shop has n jobs and m machines. Every job visits the machines in the same order, so job j's k-th operation runs on machine k.

j∈{1,…,n}
job index (Instance A: n=2, jobs Z1, Z2).
k∈{1,…,m}
operation index = machine index (Instance A: m=2, machine 1 = T lathe, machine 2 = F mill).
pjk
processing time of job j on machine k (Instance A: p11=2, p12=1, p21=1, p22=2).
Pj=∑k=1mpjk
total processing time of job j (Instance A: P1=P2=3).
xj,k,t
the bit "operation k of job j starts at hour t".

Without pruning, every operation could start at any hour t=0,1,…,H−1, so there would be n·m·H bits. Instance A at H=4: 2·2·4=16. Instance B at H=8: 3·3·8=72, the organizer's raw count.

3.2 Step 2: start windows (pruning)

Two facts remove most bits.

  • Earliest start. Operation k cannot start before the job's earlier operations are done:
    ESjk=∑l=1k−1pjl
  • Latest start. From its start, the job still needs operation k and all later ones, and must finish by H:
    LSjk=H−∑l=kmpjl

The allowed starts are the window Tjk={ESjk,ESjk+1,…,LSjk}. Its size simplifies nicely, because the two sums together cover the whole job:

|Tjk|=LSjk−ESjk+1=H−∑l=kmpjl−∑l=1k−1pjl+1=H−Pj+1

The same for every operation of a job. Adding over all jobs and operations gives the number of bits after pruning:

N=∑j=1n∑k=1m|Tjk|=m∑j=1n(H−Pj+1)

Check: Instance A, H=4: N=2[(4−3+1)+(4−3+1)]=8. Instance B, H=8, with P1=5, P2=4, P3=5: N=3[4+5+4]=39, the repository's and the organizer's pruned count.

3.5 Step 5: the job-order penalties (precedence)

General. Operation k+1 of a job may not start before operation k of the same job ends. Starting operation k at t and operation k+1 at t′ is wrong when

3.8 Step 8: finding the shortest makespan (horizon search)

Zero energy only says "a schedule exists that finishes by H". To minimise makespan, build the QUBO again with smaller H. Each step down removes m bits per job (N falls by m·n):

  • H=4: N=8 bits, one bitstring has energy 0 (above), so makespan 4 is achievable.
  • H=3: N=2[(3−3+1)+(3−3+1)]=4 bits, one start per operation (Z1·T·0, Z1·F·2, Z2·T·0, Z2·F·1). Both machines clash, and the lowest energy of all 16 bitstrings is 2. No schedule finishes by hour 3.

So the optimum is 4. Here we could check all bitstrings; a real solver cannot. Shimada et al. (2021) use the same "guess a deadline, test it" split.

A heuristic (annealer, QAOA, VeloxQ) that fails to find energy 0 at some H does not prove that H is impossible. Only an exhaustive check, an exact solver, or a lower-bound argument like the one in §1 proves that.

    5. Encodings: how many qubits do we need?
    Where we are. Section 3 built the QUBO for Instance A (2 jobs × 2 machines) with one bit per allowed start time: 8 bits at H=4. That way of turning "when does this operation start?" into bits is called an encoding, and it is not the only one. This section compares three encodings: one-hot (what section 3 used), domain wall and binary.

    5.0 Two separate steps: pruning, then encoding

    Building the bit vector involves two different decisions. Section 3 made both, but only the first one was visible:

    Step A: pruning (section 3.2)

    Decides which start hours are allowed for each operation: the list Tjk and its length Kjk. No bits are involved yet; it is just a list of hours per operation.

    Step B: encoding (this section)

    Decides how to store "which of the Kjk allowed hours" in bits. One-hot uses Kjk bits, domain wall Kjk−1, binary ⌈log2Kjk⌉.

    Section 3 used pruning + one-hot. With one-hot, every allowed hour gets its own bit, so pruning looks like "simply omit the bits of impossible hours". That is correct, but it is a property of one-hot. Other encodings store the same list of allowed hours differently.

    5.1 The decision we need to store

    General

    Take one operation o=(j,k) (job j on machine k). From section 3.2 it has

    K=H−Pj+1

    allowed start hours, from ESjk to LSjk. Number them s=0,1,…,K−1: choice s means "start at hour ESjk+s".

    Example: Z1 on the lathe, Instance A, H=5

    Z1 needs the lathe for 2 h and then the mill for 1 h, so P1=3:

    K=5−3+1=3

    ES=0, LS=5−(2+1)=2. The three choices:

    s=0: start at hour 0
    s=1: start at hour 1
    s=2: start at hour 2

    General

    An encoding is a rule that turns each allowed choice into a bit pattern:

    enc:{0,…,K−1}→{0,1}b

    Its outputs are the codewords (K of them). We never encode an impossible hour: pruning already removed those before any bits exist. But the solver does not go through enc: it searches over all 2b patterns of the qubits, because a QUBO accepts every bitstring. The 2b−K patterns that enc never produces are invalid, and the energy must punish them.

    No invalid patterns exist only if enc is a bijection, which requires K=2b (binary with K a power of 2). The price: the indicators then become products of b bits, so the energy is no longer quadratic (5.4, 5.5).

    Example

    We need 3 codewords, one per allowed start hour (hours 3 and 4 were pruned and get none). With b bits there are 2b patterns, so b≥2. Since 3 is not a power of 2, every encoding leaves at least one invalid pattern (22−3=1 at best). Which b and which patterns depends on the encoding (5.2–5.4).

    The indicator. Every rule of section 3 is built from statements "operation o starts at choice s". Write that statement as a function of the encoding's bits q=(q1,q2,…):

    xo,s(q)={1o starts at s0otherwise

    α0,α1,α2,… ("alpha")
    Fixed numbers, set by the encoding, that make up the formula for the first answer xa,s: α0 is its constant and αr is the number in front of bit qr (0 if that bit does not appear).

    5.3 Domain wall

    General

    Chancellor (2019) [PDF]: b=K−1 bits yo,1,…,yo,K−1 with the meaning

    yo,t=1⟺s≥t

    ("the operation starts later than its (t−1)-th allowed hour"). Valid codewords are a run of 1s followed by 0s; s = number of 1s. The place where the 1s stop is the "wall".

    Example

    2 bits:

    yo,1 = 1 if Z1 starts on the lathe after hour 0
    yo,2 = 1 if it starts after hour 1

    s=0:|00⟩,s=1:|10⟩,s=2:|11⟩

    Invalid: only |01⟩ ("not after 0, but after 1": impossible).

    General: indicators

    Add fixed boundary values yo,0≡1, yo,K≡0. Then

    xo,s=yo,s−yo,s+1

    "starts after hour s−1 but not after hour s" = "starts exactly at s". Linear in the y, so the energy stays quadratic.

    Example: indicators for all 4 patterns
    xo,0=1−yo,1,xo,1=yo,1−yo,2,xo,2=yo,2
    pattern |yo,1yo,2⟩xo,0xo,1xo,2meaning
    |00⟩100start at hour 0
    |10⟩010start at hour 1
    |11⟩001start at hour 2
    |01⟩1−11invalid
    General: "exactly once" is automatic

    The sum of indicators telescopes:

    ∑s=0K−1xo,s=(yo,0−yo,1)+(yo,1−yo,2)+…+(yo,K−1−yo,K)=yo,0−yo,K=1−0=1

    for every pattern, so no "exactly once" penalty is needed.

    Example
    (1−yo,1)+(yo,1−yo,2)+yo,2=1

    Check with the table: |10⟩ gives 0+1+0=1. Even the invalid |01⟩ gives 1+(−1)+1=1: the sum is right, but one "indicator" is −1. That is why the wall penalty below is still needed.

    General: wall penalty

    A −1 indicator could cancel a real clash and fake energy 0. So every "0 followed by 1" is punished:

    Pwall=λ∑t=1K−2(1−yo,t)yo,t+1

    The repository uses λ = (largest total clash weight on any single start bit) + 1, large enough that no invalid pattern can reach energy 0.

    Example

    One neighbouring pair:

    Pwall=λ(1−yo,1)yo,2=λyo,2−λyo,1yo,2
    Qwall=[0−λ0λ]

    It is λ only for |01⟩. For Instance A at H=5 the repository computes λ=5.

    General: bits for the whole instance
    NDW=∑j,k(Kjk−1)=m∑j=1n(H−Pj)=None-hot−nm

    One bit saved per operation. On annealers domain wall also beat one-hot in experiments (Chen et al. 2021 [PDF]; permutations: Codognet 2022).

    • Encoding trade-offs in general: Sawaya et al. 2023 [PDF].
    The organizer compares teams on the smallest correct 3×3 QUBO (reference: 72 raw, 39 pruned). "Correct" means: every zero-energy state decodes to a feasible schedule and every feasible schedule within H has a zero-energy encoding. Domain wall gives 30 at H=8; the repository's formulation audit checks both encodings against independent constraint counts.

    6. From QUBO to an Ising Hamiltonian

    Spin z
    A variable that is −1 or +1 instead of 0 or 1. Physicists describe qubits this way.
    Pauli-Z operator
    The quantum operation that measures a qubit as +1 or −1; Zi is that operation on qubit i.
    Hamiltonian HC
    The energy function written in the language of quantum mechanics. Same numbers as the QUBO, different notation.
    Ground state
    The lowest-energy state; for us, the best schedule.

    Quantum hardware works with spins zi∈{−1,+1} (Pauli-Z eigenvalues). Substitute xi=1−zi2:

    HC=∑ihiZi+∑i<jJijZiZj+constant
    The lowest-energy state of HC, its ground state, is the optimal bitstring. Annealers and QAOA both try to prepare it; VeloxQ and simulated annealing search for it classically. Sign conventions differ between libraries, so convert deliberately; the repository already warns not to send binary coefficients as unlabeled Ising biases.

    7. Solvers: what each one actually is

    Simulated annealing
    Start from a random bitstring and keep flipping bits; accept worse moves sometimes at first (high "temperature") and rarely later, so the search settles into a low-energy state.
    Transverse field
    In a quantum annealer, a force that keeps qubits in superposition at the start; it is slowly switched off so the qubits settle into a low-energy state.
    Embedding
    Mapping problem bits onto the hardware qubits, which are not all connected; sometimes several qubits must act as one ("chain").
    Variational algorithm
    A quantum circuit with adjustable angles; a classical computer tunes the angles to lower the measured energy. QAOA and VQE are examples. An ansatz is the chosen circuit shape.

    8. QAOA in detail, with simulated numbers

    Superposition
    A qubit state that is a weighted mix of 0 and 1; measuring gives 0 or 1 with probabilities set by the weights (amplitudes).
    |+⟩ and |+⟩⊗n
    The state "0 and 1 with equal weight"; ⊗n means all n qubits start that way, so every bitstring is equally likely.
    Cost layer e−iγHC
    A circuit step that gives each bitstring a phase proportional to its energy. γ (gamma) is its adjustable angle.
    Mixer layer e−iβHM
    A step that moves weight between bitstrings so that good ones can grow. β (beta) is its angle; Xi flips qubit i.
    Depth p
    How many cost+mixer rounds the circuit has. More rounds = more angles to tune, usually better results, deeper circuits.
    Shots / sampling
    Running the circuit many times and recording the measured bitstrings.
    Statevector simulation
    Computing the exact quantum state on a classical computer, possible only for few qubits.
    COBYLA
    A standard classical optimiser used to tune the angles.

    QAOA prepares |+⟩⊗n and applies p rounds of

    U(γ,β)=e−iβpHMe−iγpHC⋯e−iβ1HMe−iγ1HC,HM=∑iXi
    A classical optimiser tunes the 2p angles to lower the measured energy; the circuit is then sampled and each bitstring is decoded and validated. The cost layer e−iγHC needs one RZ per linear term and one RZZ per coupling, so fewer couplings mean shallower circuits. Kurowski et al. (2023) applied exactly this to the time-indexed job-shop QUBO.

    Read the table as a lesson about formulations rather than about quantum speed:

    1. Infeasible states waste amplitude. With the plain X mixer, the 8-qubit one-hot circuit spends most probability on bitstrings that are not even valid encodings (P(valid) ≤ 0.43).
    2. Constraint-preserving mixers fix this. The XY mixer 12(XaXb+YaYb) moves the single 1 between the two start bits of the same operation, so starting from a superposition of valid states it never leaves them (Hadfield et al. 2019 [PDF]; Wang et al. 2020 [PDF]; Fuchs et al. 2022 [PDF]).
    3. Domain wall and XY are equivalent here. With two starts per operation, the XY mixer on a one-hot pair acts exactly like an X rotation on the single domain-wall bit, so the two rows match while the domain-wall circuit uses half the qubits. With more starts per operation the two approaches differ.
    4. Cross-check with the repository. An earlier shared-X p = 3 QAOA run on the domain-wall model reports 3636/4096 = 0.888 feasible shots; this independent simulation gives P(optimal) = 0.886 (at H = 4 the only feasible state is the optimum). They agree within shot noise.

    CVaR: optimise the best samples, not the average

    Barkoutsos et al. 2020 [PDF] replace the mean energy with the average over the best fraction α of shots. On the 8-qubit one-hot X-mixer model:

    pobjectiveP(optimal)⟨E⟩

    CVaR modestly raised P(optimal) at p = 2 (0.081 → 0.100) while making the average worse, which is the intended trade-off. On this tiny model, changing the encoding or mixer matters far more than changing the objective. Warm starts from a classical solution (Egger et al. 2021 [PDF]) are the other common add-on, and Lopez-Ruiz et al. 2025 [PDF] (preprint) show a non-variational, iterative warm-started QAOA on job-shop instances.

    Simulated QAOA on 4–8 qubits is exact linear algebra on a laptop. It demonstrates correctness of the formulation and pipeline, not quantum advantage. Say so in the presentation.

    9. Penalties when an objective appears

    Objective
    What we want to make small among valid schedules (makespan, lateness, cost).
    Penalty weight A, objective weight B
    Multipliers that set how much breaking a rule costs compared with a worse objective.
    Slack bits
    Extra bits added to turn an inequality ("finish by hour 5") into an equality; they cost qubits.

    As long as the QUBO only encodes feasibility, all weights can be 1. Stage 2 adds objectives (tardiness, setup costs, schedule churn), and then

    E=A·Econstraints+B·Eobjective
    If A is too small, breaking a rule can lower the total energy; if A is too large, the objective is a ripple on a huge landscape and heuristic solvers struggle. A safe rule: A must exceed the largest objective improvement any single violation could buy. References: Verma & Lewis 2020 (bounds, partitioning), Ayodele 2022 [PDF] (permutation problems), Phillipson & Hutten 2026 (penalty sensitivity on parallel machines).

    Inequalities such as "finish job j by its due date" normally need slack bits. Unbalanced penalization (Montañez-Barrera et al. 2024 [PDF]) uses an asymmetric penalty that punishes violation strongly and slack weakly, with no extra qubits; the trade-off is that the optimum is only approximately at the ground state and must be checked.

    10. Hybrid methods and where VeloxQ fits

    Hybrid method
    A classical program that calls a QUBO solver only for part of the work.
    Neighbourhood
    A small part of the schedule we allow to change while the rest stays fixed.
    Large-neighbourhood search (LNS)
    Repeat: pick a neighbourhood, re-optimise it, keep the change if it is better.
    Constraint programming (CP, CP-SAT)
    Classical exact solvers that handle scheduling rules directly; Google OR-Tools CP-SAT is a common one.
    Restriction gap
    How much worse re-optimising only a neighbourhood is than re-optimising everything.

    Across the literature, QUBO solvers do best inside a classical search rather than as a stand-alone scheduler. Zhang, Lo Bianco & Beck (2022) [PDF] found direct job-shop QUBOs uncompetitive, but a large-neighbourhood search (LNS) using a QUBO solver on sub-problems and constraint programming for the rest beat CP-based LNS and MIP.

    schedule = feasible starting schedule (e.g. CP-SAT or a dispatch rule)
repeat:
    freeze everything already executed (rolling planning / disruption)
    pick a neighbourhood: a time window, a machine, the jobs hit by an outage
    build the residual time-indexed QUBO for that neighbourhood only
    sample it with VeloxQ (many low-energy samples per call)
    decode and validate each sample against the FULL model
    accept the best valid improvement; log the restriction gap vs CP-SAT
until time budget or no improvement

    Why this suits VeloxQ: it is reported to handle very large sparse QUBOs and returns many samples quickly (Pawłowski et al. 2025 [PDF]), and a railway case study found it beat D-Wave on small instances, while generating the QUBO, not solving it, became the bottleneck at scale (Kędziera et al. 2025 [PDF], preprint). Small residual QUBOs avoid that bottleneck. Published precedents for the disruption story: rescheduling with a rescheduling-effort objective (Schworm et al. 2024), machine unavailability (Aggoune & Deleplanque 2024), AGVs (Geitz et al. 2022 [PDF]) and Polish railway conflict management (Domino et al. 2023 [PDF]).

    A compelling VeloxQ entry measures, on the same instances: feasibility rate, best makespan or objective, time-to-target, restriction gap (neighbourhood vs full re-optimisation), and comparisons with simulated annealing and CP-SAT, across instance sizes and several seeds.

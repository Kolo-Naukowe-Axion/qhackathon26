# Observed CPU-simulation runtime and quality

The retained final episodes took about **2.5–10.6 process CPU seconds for the cheap controllers**, versus **113–255 seconds for MPC**, across the 12/16/24-order, 96-hour factory contexts. These observations answer the practical inference-cost question on the measured Axion CPU setup. They do not establish hardware-independent speedup or a new policy selection.

| 12 | `static-grid-12` | 3.331 | 0.07500 | `mpc-4future-12` | 156.190 | 0.03766 |

MPC improves the point estimate against the preselected controller at 12/16 orders and regresses at 24. Each method has 256 reserved environmental tapes: 32 per uncertainty leaf, weighted by the leaf's true probability divided by 32. Local stochastic controls have three actor seeds, averaged within each environment: 768 executions represent **256 environments**, not 768 factories. The export independently recomputes every displayed timing/quality mean from the original retained episode rows; all 12,288 included executions are valid. Corresponding physical instance hashes agree across the methods. Missing includes realized urgent demand. Zero observed n24 completions does not prove impossibility. Raw horizon-censored deadline debt is retained in CSV/JSON and includes unfinished orders' cutoff debt, rather than only delivered-order lateness.

Measured episode process CPU includes checkpoint/setup work, simulation, online MPC continuation planning and local optimization, and independent physical checking. Planning, checking and inference sub-timers are nested; adding them to episode CPU would double-count work. Startup/import overhead and trace serialization are not completely included. CPU seconds are not campaign elapsed time or bare solver latency. Actual runtime metadata records Linux x86_64, Python 3.12.13, CPU-only Torch, 32 allocated CPUs per job, and one-thread numerical libraries; no exact CPU model was retained. Cohort-specific SLURM IDs, package versions and frozen source versions are in the [report](../output/stage2-search/final-runtime-tradeoffs/report.json). These are observed runtime comparisons, not normalized speedups; the methods have different outer controls, action domains, search histories and online budgets. Only the no-batch SA/QAOA/uniform subset shares the declared matched local-selector experiment. QAOA is CPU statevector simulation with at most five actual qubits and explicit larger-subproblem classical fallbacks; it does not require a quantum machine for these tests.

The neural/schedule fits were not free pretraining. Their checkpoint metadata records one shared fit across all three loads: PPO6-2026 used 9,048 fit/816 reused-validation episodes in 1,200.165 seconds; PPO6-2027 used 9,368/816 in 1,205.536 seconds; CEM6-2026 used 9,096/720 in 1,216.086 seconds. Each configured 32 workers. These wall durations are not measured process CPU, and must neither be multiplied by final episodes nor added again to the ledger. The export deduplicates these costs by checkpoint SHA. Static searches, shared strong-prior development, selector reward studies and MPC selection also belong to the shared development history; no unsupported per-method allocation is invented.

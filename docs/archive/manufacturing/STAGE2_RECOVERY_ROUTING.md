# Recovery and scoped routing: TRAIN diagnostics

`stage2/recovery_routing.py` composes the frozen physical kit-repacking policy with existing process-scoped routing and optional family admission. It changes scheduling decisions only. The original moves, worker calendars, machine durations, storage bounds, maintenance and quality model remain enforced by the independent checker.

The first experiment deliberately selected eight previously failed TRAIN instances: n12/seed15; n13/seeds3,5,20; n14/seeds0,3,6,31. Its96 runs compare WIP4/6/8, QA guard0/4 and QA-only finish-time routing off/on. All96 passed the checker; wall time was191.54s on two local workers. Full sources, protocol, terminal inventories, raw rows and failures are retained in `output/stage2-search/recovery-routing-targeted-training/`. Completion rates on these selected failures are development evidence, not unbiased performance estimates.

For n13, WIP6/guard4/routing-off shipped45/45 across the three selected tapes, versus40/45 for the frozen WIP8/guard4 control. For n14, WIP6/guard4/QA-routing shipped60/64 and completed two of four tapes, versus54/64 and zero complete for the control. QA routing alone is not consistently beneficial: n13 WIP6/guard4 fell from45 to44 shipments when enabled. The predeclared384-episode paired TRAIN0–31 follow-up is `output/stage2-search/recovery-routing-paired-train32-tasks.json`; it must be evaluated before promoting a choice. No new validation or final tapes were run.

The n12/seed15 diagnosis separates quality from late scheduling. Original order P11's final pump fails both allowed QA attempts and is permanently scrapped. Urgent order U01 has its accepted components ready too late for assembly. These are not two urgent misses. The P11 first QA draw is below the standard assembly risk floor, and its second draw is below the fixed repair residual risk. This establishes failure for that standard-mode trajectory, not impossibility for all legal policies: careful assembly is a legal, slower mode and may change the first inspection outcome.

The remaining n13 trajectories predominantly leave QA work near the horizon. The fact that WIP changes complete all three selected tapes proves scheduling losses on those tapes. Calendar utilization is only descriptive: shared skills, location, shifts and release chronology prevent treating aggregate utilization as an infeasibility certificate. The n14 results likewise do not establish a hard capacity boundary. All terminal inventories and QA-qualified worker occupied/calendar minutes remain available for diagnosis.

Run the frozen follow-up using `python -m stage2.recovery_routing --tasks output/stage2-search/recovery-routing-paired-train32-tasks.json --output <new-directory> --workers 32`. The driver rejects non-TRAIN seeds, source drift and output overwrite, and retains invalid rows. Recovery is a bounded heuristic with known possible residual deadlocks; this composition makes no universal guarantee.

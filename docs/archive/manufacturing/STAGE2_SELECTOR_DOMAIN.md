# Fixed crew domains and reward failure

The original factory previews one crew assignment for each offered operation. Its exact selector optimizes compatible subsets of those fixed assignments. Priority dispatch instead commits sequentially and may choose a different worker after an earlier commitment. This is a real difference in candidate domains; it does not establish that worker-domain loss explains the observed exact-selector collapse.

`stage2/selector_domain.py` audits this difference and optionally enumerates complete operation-plus-crew alternatives. Default mode is off and calls the original factory loop directly. The opt-in loop is derived from the frozen physical loop by exactly three declared hooks: expand offers/requests; prepare selected crews; verify commitments. An AST round-trip removes the hooks and requires exact equality with the original statements, and an engine-source SHA guard rejects physical source drift. The original physical process, movement, calendars and checker are unchanged.

Each alternative specifies a primary worker and, when needed, a separate setup worker. Enumeration calls the original physical preview under a temporary worker restriction, restored in `finally`, and deduplicates complete worker intervals. It includes the original assignment. The original dispatch constructor then enforces all same-unit, machine, tool, overlapping-worker and cumulative-power constraints. Three simultaneous jobs with only two qualifying workers cannot evade capacity through pairwise crew alternatives. Selected alternatives commit with those exact workers; both candidate IDs and full physical assignments must match. The optional classical reference defaults to an18-core-candidate cap, disclosing fallback to the original domain when exceeded. This is not an18-total-qubit cap: power slack is counted separately. Enumeration does not introduce alternative machines, portable-tool assignments or new physical capabilities.

Six tests cover default physical equivalence, AST drift guards, an actual two-job worker-domain example, a three-job/two-worker Hall fixture, exception restoration, physical checking, paired causality and assignment identity. The initial eight n12 TRAIN runs all passed the full checker but do not promote the expanded selector: for seeds0/1/2/4, frozen exact ships13/12/10/2 while expanded exact ships13/12/1/2. Expanding the domain can worsen a myopic objective. Full evidence is in `output/stage2-search/selector-domain-training-audit/`. Its exported real crew pools include14 core plus9 power-slack bits,23 total; simulator benchmarking must retain those auxiliaries.

A broader audit examines the first64 structurally distinct coupled pools on each matched priority/exact trajectory for TRAIN0/1/2/4,52 on the short seed4 exact trajectory. One sampled pool has strict worker-domain reward loss: seed2/exact/tick1030. WASH books W08 for5minutes; a subsequent turning start can use W10 for setup and W08 for later processing. The frozen offer instead assigned W08 to a combined50minute block, spuriously conflicting with WASH. Sequential dispatch changes the turning crew and attains reward508.57 versus497.14, with the same number of starts. This is a bounded sample, not an exhaustive claim that no other losses occur. All pools and shadow assignments are retained in `output/stage2-search/selector-domain-broad-boundary-training/`; shadow commits execute no future completions or QA outcomes and are explicitly not measured full runs.

The first priority/exact divergence is much more consequential and has a different cause. All four tapes share the same physical prefix through tick420. Exact selects P05's two-part HEAT batch, reward307.55, over higher-priority P07's single rotor, reward298.11. They share H2/W02. P05 also incurs setup and35minutes of worker attendance versus5minutes for P07. The extra100 reward per batch unit overwhelms the normalized priority difference by construction. This is strict objective preference, not a tie or alternative-worker effect.

Forcing only the priority subset at tick420, then resuming exact everywhere else, improves seed2 from10/14 to14/14 shipments and seed4 from2/12 to12/12. Seed0 stays13/14 and seed1 stays12/12. All four actual traces pass the independent checker and selected/committed checks, with identical pre-intervention physical prefixes and candidate pools. These selected retrospective interventions demonstrate a causal trajectory mechanism, not global optimality or an unbiased success-rate estimate. Evidence is retained in `output/stage2-search/selector-first-divergence-training/`. Reward-only controls are documented separately in `STAGE2_SELECTOR_REWARD.md`.

# Bounded18-action speed/quality/wear experiment

`stage2/adaptive_modes.py` is a separate CPU PPO/CEM experiment. It leaves the held six-action `adaptive_recovery.py`, physical engine, numerical spec and core checker unchanged. Its18 actions are the Cartesian product of WIP4/6/8, QA guard0/4 and T/F processing mode eco/standard/turbo. Assembly/welding modes remain unchanged; precision certification automatically excludes illegal turbo choices through the original factory logic.

The model uses the same32 public observation features, a32–64–64 actor/critic MLP and720-minute decisions. PPO is state-dependent during training and evaluated by deterministic argmax. CEM searches eight time segments and must be described as a time policy. An exact static incumbent stays eligible for every context's repeated validation selection. Active operations and reservations remain committed when a macro changes.

Execution explicitly uses `maintenance_guard.run(..., maintenance_outage_guard=True)`. This causal algorithm restriction skips maintenance that would overlap observed outages or any unrevealed public outage support. It does not read the hidden realized branch or modify physics. Both anchored physical replay and the separate canonical identity audit check every rollout; metrics are independently reconciled before reward calculation.

The declared contexts are full minute-grid H5760 at12/16/24 initial orders. Priors are conservatively development-selected:12 starts standard/WIP8/guard4,16 starts standard/WIP6/guard4,24 keeps its original v12 fallback. For16 orders, the reported TRAIN32 static mean missing counts motivating that prior were2.71875 standard versus2.90625 eco and3.4375 turbo at WIP6/guard4. Those static development results are prior evidence, not performance of the new learner.

Two bounded fits use seed2026: PPO600s and CEM600s, each at most32 CPUs, no GPU. Factory fitting draws only TRAIN0–31; checkpoint selection reuses VAL100–115. The budget is soft at complete-batch boundaries; actual wall and allocation must be reported. Reserved final tapes remain untouched. The aim is to test whether changing processing speed can improve the already strong controller; no gain or dynamic advantage is presumed.

## Interpretation required before claiming progress

The six-action PPO2026 policy was constant WIP6/guard4 throughout all sixteen validation trajectories at both12 and16 orders. Matching static controls reproduce every physical list and metric. PPO2027's16-order4→6 WIP switch lost to constant6/4. A learned network choosing a better constant is useful parameter search, without evidence of dynamic control advantage. These matched diagnostics are retained in `axion-adaptive-evidence-2349/ppo-physical-comparison.json` and use reused validation after selection.

The18-action experiment must be compared with matching static modes/controllers as well. More actions, nonzero action changes, probability amplification, or improvement over a weaker incumbent cannot by themselves establish state-dependent benefit. All selected policies and failures should remain visible. Cost must include prior search/cloning, training, validation and any post-selection static diagnostics.
